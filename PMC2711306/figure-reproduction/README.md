## What the code does against the paper

| Step | Paper | Here |
| --- | --- | --- |
| Yhigh | Collins et al.'s high-confidence set, 9,074 edges; largest component 1,004 proteins and 8,323 edges | Collins et al.'s combined PE scores (interactome-cmp.ucsf.edu, Wayback Machine 2010-07-15), PE >= 3.19: 9,070 edges; largest component 1,004 proteins and 8,319 edges |
| Test positives | "low confidence edges" of the Collins network, not defined further | Pairs between Yhigh proteins with 1.85 <= PE < 3.19 (5,356): Collins et al. clustered down to PE 1.85, and the (TP, FP) labels of Fig. 2 imply about 5,296 |
| HumanBG | BioGRID 2.0.35, Table S7 systems: 7,930 proteins and 23,543 edges; largest component 7,513 and 23,372 | Upper-cased official symbols (the BioGRID ID where there is none), any partner organism, self-interactions dropped: 7,792 and 23,538; largest component 7,514 and 23,378 |
| Embedding | MDS of sqrt(path length) with an upper threshold, subspace iteration ("for practical details see [18]") | As the authors' `embed_novi.m`: path lengths up to 29, unreachable pairs at 200 (P = L - 200, 0 where unreachable), the diagonal at 2 (the closed walk the code's matrix powers record), the top eigenvectors scaled by sqrt(eigenvalue) and each axis rescaled to [0, 1]. Eigenpairs solved exactly (ARPACK); the authors' iteration stops at a change of 1e-3 |
| Algorithm 1 | Non-edges closer than epsilon; epsilon swept from 0 to the largest distance | The same; markers at the epsilon grid read from the figures |
| Iteration (Fig. 4) | Add the predictions and re-embed until convergence | Re-embed until no new pair is predicted; when the graph becomes so dense that the leading eigenvalues are not positive (epsilon >= 0.7), every pair is predicted |
| Deletions (Fig. 5) | Remove 500 to 3,000 random edges and recover them | Embed the largest component of what is left (the method's rule); deleted edges cut off from it stay false negatives; mean of 10 deletions per size |
| Algorithm 2 | Three-Gaussian EM mixtures for edges and non-edges, posterior with a prior, CS >= 0.975 within distance 0.4 | As `assign_scores.m` and `EM.m`: 18,000 distances drawn with replacement from each class, EM started from 30 of the first 100 values, stopped when the log-likelihood (checked every 10 iterations) changes by less than 0.01, P(edge) = 0.001, scores divided by the largest |
| Validation | HPRD (release not named), BioGRID 2.0.50, GO (release not named), KEGG March 2009, CiteXplorer | BioGRID 2.0.50; HPRD release 9 (2010, Pathway Commons 2); GOA human release 70 (February 2009, the closest of releases 67-74 to the paper's counts); current KEGG; CiteXplorer not attempted |

The method itself is the package [`../package`](../package) (`geodenoise`); the pipeline imports
it. The port check runs the authors' `embed_novi.m` under GNU Octave 10.3 (with shims for `dist`
from the Neural Network Toolbox and `mvnpdf` from the Statistics Toolbox) on Yhigh in dimensions 2
to 7: distances differ by at most 0.018 and the ROC counts at the epsilon grid by at most 0.9%.

## Run

From the repository root, with Python 3.12, `pip install -r PMC2711306/figure-reproduction/requirements.txt ./PMC2711306/package`, uv, Java 21 and Nextflow 25.04.6:

```bash
nextflow run PMC2711306/figure-reproduction/main.nf --outdir results                  # the pull-request run, about 15 min on 4 cores
nextflow run PMC2711306/figure-reproduction/main.nf --outdir results --full           # also the Collins scores, GO, HPRD and KEGG
nextflow run PMC2711306/figure-reproduction/main.nf --outdir results --octave_check   # also the authors' Matlab under GNU Octave
sbatch PMC2711306/figure-reproduction/run_skyriver.sbatch --full --octave_check       # on the Skyriver cluster
```

The workflow `.github/workflows/reproduce-pmc2711306.yml` runs the first command on every pull
request and push that touches this folder; started by hand it takes `full` and `octave` inputs.
A light run reads `output/run/validate.json` and `output/run/port_check.json` instead of
recomputing them, and the Yhigh networks from `pipeline/inputs/`: their sources (the Wayback
Machine, EBI, KEGG) are too unreliable, or change too often, for every pull request.

## Pipeline steps

1. `FETCH`: downloads with SHA-256 checks (KEGG has no fixed checksum: it changes with each release).
2. `SUPPLEMENT`: Tables S1-S7 as JSON.
3. `NETWORKS`: HumanBG and Yhigh; every file must equal the committed `pipeline/inputs`.
4. `YEAST`, `HUMAN`: the experiments.
5. `VALIDATE` (full), `PORT_CHECK` (octave_check), `ARITHMETIC`.
6. `FIGURES`: renders, overlays, scores and controls.
7. `PACKAGE`: `check_package.py` on `../package`.
8. `RESULTS`: `results.json` (verdicts by `check_results.py`), the check against the committed outputs (`report.md`), and the results page.

## Limits

- Figures are scored by pixels at 2 px on the 300 dpi originals. Excel draws smoothed lines through the markers; we draw them the same way (Catmull-Rom curves through our points at the paper's epsilons), so the line between markers is ours, not Excel's.
- Fig. 5's dimension and number of repeats are not stated; the dimension is chosen by score (recorded as a search).
- The EM fit (training sample and start) is random in the authors' code; Table S1's count and Figs 1B and S1-S3 move with it. We report one seed and the spread over 20.
- HPRD's 2009 release and KEGG of March 2009 are not available; the later releases stand in for them.
- `package.json` records the machine's Python and paths; the check step leaves it out of the comparison with the committed outputs.
