GABi 0.1 and the S1 bicluster models

What the code behind Curry (2014), BMC Bioinformatics 15:355, computes, and where it differs from the paper

The paper describes GABi, a genetic algorithm (GA) that searches over column subsets J and scores each J with a model-specific fitness function. The fitness function picks the rows I by rule. The code is the CRAN package GABi 0.1, which holds the GA, plus Additional file 1 (S1), which holds the R code for the paper's four bicluster models. This folder records what that code computes and where it departs from the paper. Every claimed difference has a small executable check.

Method

  • Read R/*.R and man/*.Rd of GABi 0.1, the S1 code, and the paper: Algorithm 1 and "Parameter setting" (pp 5-6), Eqs 14-44 (pp 7-8), Eq 45 and Algorithm 2 (p 9), and the synthetic offsets (p 10).
  • Ran the authors' code: GABi from the installed library, with S1 sys.sourced from sources/. Check 01 confirms that the installed functions are the tarball's. To read intermediate values without copying code, checks/common.R has three helpers. instrument() returns an S1 function's local variables in place of its result. patch() swaps exactly one source fragment, to test a proposed fix. trace() is used on GABi namespace functions.
  • reference/paper_models.R implements Eqs 14-16, 17-23, 24-29, 31-35, 45 and Algorithm 2 from the paper alone. Where a formula is inconsistent with its text, the function has a switch for the printed form and the evident intent. Check 12 compares it with S1 on random Algorithm 2 inputs.
  • R 4.6.1, survival 3.8.6, hash 2.2.6.4. The Fig 2 benchmark and the TCGA analysis were not run here. They are in ../figure-reproduction/.
  • Status column below: exec means shown by running the code (check id given). read means from reading the code only.

Recovered algorithm (GABi() with defaults)

x: features x samples. A solution is a 0/1 vector over the columns (samples).
fitnessArgs$tabu <- list(features = 0, samples = 0)                     # GABi.R:5, overwrites any user tabu
diffRows <- rows that are not constant and whose min-max scaled row mean is
            in [1 - diffThreshold, diffThreshold] = [0.1, 0.9]           # GABi.R:7-18; not in the paper
fitnessFun and featureSelFun get GABi's frame as enclosure, so they read x, diffRows,
row.mins, row.maxes, fitnessArgs from there                             # GABi.R:29-32
repeat while length(allSols) <= nSols (0) and loop < maxLoop (1):       # GABi.R:37
  4 demes x ceiling(256/4) = 64 solutions, each with exactly 2 random columns set   # GABi.R:40-45
  cache: chromosome string -> fitness (one hash per loop)               # GABi.R:58
  for gen in 1..maxNgens (200), until converged:
    for each deme j:
      fitness of uncached rows; Inf and NA -> 0                         # GABi.R:69-91
      best_j <- first row with maximal fitness
      stagnant_j <- best_j identical to any current best_k (k = 1..4); otherwise counter <- 0
      if counter >= convergenceGens (40): converged; skip this deme     # GABi.R:108, 187-190
      while all fitnesses == 0:                                         # GABi.R:110-158
        "re-initialise": rows[i, 2 random cols] == 1  (comparison; the deme stays all 0)
        after 100 tries: diffThreshold += 0.1; if > 1: warning, return(list())
      selection: row 1 <- argmax (elite); rows 2..64 <- roulette over rows with fitness > 0  # fps.R
      crossover: each non-elite row independently with prob xfreq (0.5); shuffle the picked rows
        and pair them; one-point cut k ~ round(U(1, n)) (k = n acts as n - 1); an odd row is kept  # reproduction.R, crossover.R
      mutation: each bit of rows 2..64 flips with prob mfreq/ncol = 1/n  # mutation.R
    if all 4 demes stagnant: counter += 1                               # GABi.R:192-194
    every experiod (10) gens: exchangeSols(new demes, fitnesses of the previous population)  # GABi.R:195-198
      k_i <- argmax of old fitness in deme i; migrant_i <- new deme i row k_i
      deme i row k_i <- migrant_{pi(i)}, pi a random permutation        # exchange_sols.R:9-11, 33-38
  final: pool all demes, recompute fitness (Inf/NA -> 0), keep rows with fitness > 0  # GABi.R:201-211
  dedup in population order: a new solution evicts every kept solution with
    |A n B| / min(|A|, |B|) > identityThreshold (0.75) over sample sets; the best of that group stays  # GABi.R:212-230
  each kept solution -> list(samples, features = featureSelFun(samples), score = fitnessFun(chr))  # GABi.R:232
  tabu <- union(tabu, returned features and samples)                    # GABi.R:237-244
return allSols

keepBest = TRUE keeps a de-duplicated archive of every positive-fitness solution seen during the run, and the final population is merged into it (GABi.R:165-181, 213-216). The Rd file describes keepBest as elitism. Elitism is in fact always on (GABi.R:183, 185).

What could change the published results

Fig 2 (block, cor and highvar models on Algorithm 2 data, n = 100, m = 20), most to least:

  1. Cor model: C2, C6 and C1/C3. Wrong-row p-values, a size preference from R's Spearman p-values, and a different seed and row gate from Eqs 17-23. Combined with G2, the cor GA starts only through the block fallback, and with θ ≥ 1 GABi returns nothing. Which of these bite depends on θ and ρ, which the paper does not give.
  2. Highvar model: V2 favours J smaller than the implanted one. The paper's formula has the same flaw, so the published panel already reflects it.
  3. GA framework (G7, G10-G13): affects search quality, not the objective. Not quantified.
  4. G5 does not apply (no rows dropped). The block model matches the paper (B1).

TCGA bicluster (dysregulation-vs-outcome model, |J| = 21), most to least:

  1. D1: under R 4.6.1, a 21-sample J scores 0 if any candidate CpG has |ρ| with the seed in 0.836-0.865 (and the ρ gate is below 0.836), or if the seed row has a tie. Not tested on 2013-era R.
  2. D3 and D4: during the search, h and I″ are computed on different rows from the ones the reported bicluster uses.
  3. G5 and D5: rows are removed before the model sees them (scaled mean outside [0.1, 0.9]), and rows high or low on J are never correlation candidates. Not quantified without the TCGA data.
  4. D2: no effect on a correlation-branch bicluster. It only changes the branch choice through the missing low rows.
